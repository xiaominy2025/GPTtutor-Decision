# Engent Labs V1.6.6 — Backend Logic Summary (Updated)

## 1. Query Processing Logic 
• **Relevance Scoring**: Each query is scored using a formula: 2× concepts matched + # of domains + application field presence. 
• **Query Rejection**: Queries scoring below threshold (score < 2) are rejected before GPT is called.
• **Lazy Loading**: Backend loads course data and models on demand; reuses in-memory cache for faster performance.
• **Retry API Calls**: GPT calls are wrapped in retry logic with exponential backoff for robustness. 

## 2. Semantic Extraction & Concept Selection
• **Domain Detection**: Uses hybrid semantic similarity + keyword triggers to classify into behavioral, technical, strategic, or negotiation domains. 
• **Application Field Detection**: Uses hybrid semantic and keyword-based logic to infer context (e.g. finance, leadership, startup, operations_management, people_talent_career). 
• **Concept Extraction**: Embeds both the query and 60+ glossary concepts, then ranks them by cosine similarity + alias matching + pattern boosts + systematic context analysis.
• **Systematic Context Analysis**: Analyzes semantic context mismatch between query and concept definitions to apply context-aware penalties (e.g., bidding concepts penalized in career contexts).
• **Fuzzy Matching**: Fallback matching used when semantic similarity fails, with threshold 0.8. 
• **Concept Prioritization**: Penalizes generic matches and prioritizes domain-aligned and core concepts. Max 4 final concepts shown. 

## 3. Structured Answer Generation Logic
• **Initial GPT Call**: Combines system prompt + query + extracted concepts + application field into a single prompt to GPT. 
• **Strategic Thinking Lens**: GPT generates an analytical explanation based on domain logic. 
• **Story in Action**: Either included in GPT output or replaced with fallback story matched to application field.
• **Merging Logic**: If needed, the lens and story drafts are merged via a second GPT call to produce a coherent answer.
• **Follow-up Prompts**: Auto-generated by GPT or replaced with domain-appropriate fallbacks.
• **Concepts Section**: **ALWAYS uses authoritative concepts from query-engine concept extraction. GPT output concepts are completely ignored.**

## 4. Final Output Assembly 
• **Structure Enforcement**: Output must include Strategic Thinking Lens, Follow-Up Prompts, Concepts & Tools (strict formatting). 
• **Bullet Sanitization**: Cleans bullets/markdown before returning answer. 
• **Final concept list is deduplicated, capped at 4, and sent back as JSON array for UI tooltips**
• **Application Field**: Included in structured response for Lambda function consumption.

## 5. Engent Labs V1.6.6 Answer Structure & Logics
Every answer has 4 sections, created in sequence with fallbacks to ensure quality and completeness.

### 5.4 Follow up Prompts

## 6. Domain Extraction Function Summary (Engent Labs v1.6.6.6)

### 6.1 Semantic Detection
**Function**: `detect_domain_semantic(query)`
• **Reference set**: 79 example queries (Strategic 40, Technical 30, Behavioral 40, Negotiation 20).
• **Process**:
  - Embedding similarity vs. references.
  - Normalize scores (0–1).
  - Cluster-based selection with stricter thresholds.
• **Selection Parameters**:
  - primary_min_score = 0.45
  - gap_threshold = 0.12
  - max_domains = 3
• **Strengths**: Comprehensive coverage, finds all semantically close domains.
• **Limitations**: May over-include without cluster filtering.

### 6.2 Keyword Detection
**Function**: `detect_course_concept_domains(query)`
• **Reference set**: Weighted keyword list.
  - Strong = +3 (e.g., "strategy", "negotiate", "simulation").
  - Modest = +2 (e.g., "team", "production", "merger").
  - Weak = +1 (e.g., "career", "offer", "stress").
• **Process**:
  - Score per keyword hit.
  - Normalize into percentages.
  - Cluster-based selection with looser thresholds.
• **Selection Parameters**:
  - primary_min_score = 0.30
  - gap_threshold = 0.15
  - max_domains = 3
• **Strengths**: Reliable, interpretable, no API dependence.
• **Limitations**: Dependent on keyword list quality.

### 6.3 Hybrid Detection
**Function**: `hybrid_domain_detection(query)`
• **Process**:
  - Run semantic and keyword methods.
  - **Combine results using AVERAGE (not max) to prevent over-ranking single-method domains**.
  - Apply cluster-based selection with balanced thresholds.
• **Selection Parameters**:
  - primary_min_score = 0.38
  - gap_threshold = 0.14
  - max_domains = 3 (sometimes 4 for strong multi-domain queries)
• **Strengths**: Best production choice; selective, balanced, reduces noise.
• **Limitations**: May trim weaker domains in 3–4 domain cases (by design).

### 6.4 General Domain Handling
• Always removed before clustering to avoid diluting scores.
• Returned only as fallback if no specific domain passes filters:
• `return {"general": 1.0}`

### 6.5 At-a-Glance Parameter Table
| Method | Min Score | Gap Threshold | Max Domains | Notes |
|--------|-----------|---------------|-------------|-------|
| Semantic | 0.45 | 0.12 | 3 | Stricter, high precision |
| Keyword | 0.30 | 0.15 | 3 | Looser, interpretable |
| Hybrid | 0.38 | 0.14 | 3 (4) | Balanced, best for production |
| General | N/A | N/A | Fallback | Returned only if nothing else |

### 6.6 Overall Behavior:
• **Semantic** = maximum recall
• **Keyword** = stable, rule-based
• **Hybrid** = precision-focused (production default)

**Domain extraction Flow**:
`process_query` → `unified_semantic_extraction` → `hybrid_domain_detection` →
  - `detect_domain_semantic` (embeddings)
  - + `detect_course_concept_domains` (keywords)
→ **combine by AVERAGE score** → cluster-based filtering → final domains.

## 7. Concept Scoring Logic (Updated V1.6.6)

### 7.1 Base Scoring Formula
```
score = base_similarity + alias_boost + pattern_boost - generic_penalty + context_boost - context_penalty
if core_concept: score *= 1.2
```

### 7.2 Scoring Components
• **Base Similarity**: Cosine similarity between query and concept embeddings
• **Alias Boost**: +0.15 if query contains any concept alias
• **Pattern Boost**: +0.15 for each regex pattern match in concept definition
• **Generic Penalties**: 
  - swot analysis: -0.20
  - strategic framing: -0.15
  - competitive advantage analysis: -0.10
  - risk assessment: -0.25
  - leadership assessment: -0.25
  - porter's five forces: -0.05
• **Core Boost**: 1.2x multiplier for core concepts
• **Context Boost**: +0.03 for evaluation/option-related concepts when query contains "evaluation" or "option"
• **Context Penalty**: Systematic semantic context mismatch analysis (0.05-0.20 penalty)

### 7.3 Systematic Context Analysis
• **Query Context Analysis**: Identifies decision type (career, bidding, investment, project, operations), scope (binary, single, multiple), and domain
• **Concept Context Analysis**: Analyzes concept definition for decision type, scope, and specificity
• **Context Penalty Calculation**: 
  - Decision type mismatch: -0.12
  - Scope mismatch: -0.08 (multi-scope in binary decision) or -0.05 (binary in multi-scope)
  - Domain mismatch: -0.06
  - Maximum penalty cap: 0.20
