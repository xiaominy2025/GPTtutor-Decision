## 🔧 Technical Implementation Details

### Course Loading Flow
1. **Frontend Request**: Sends `course_id` parameter in query request
2. **API Server**: Calls `load_course_config(course_id)` function
3. **Validation**: Checks if course directory exists, falls back to "decision" if invalid
4. **File Loading**: Loads `glossary.json`, `prompt_template.txt`, `sections_config.json`
5. **Query Processing**: Passes course configuration to `query_engine.process_query()`
6. **Response**: Returns course-specific answer with appropriate concepts and tooltips

### Error Handling Strategy
- **Missing course_id**: Defaults to "decision" course
- **Invalid course_id**: Logs warning and uses default course
- **Missing files**: Gracefully handles missing configuration files with empty defaults
- **API errors**: Returns appropriate HTTP status codes with informative messages

### Performance Optimizations
- **Lazy Loading**: Course configurations loaded only when needed
- **Efficient Fallbacks**: Quick fallback to default course
- **Caching**: Course configs cached during session
- **Memory Management**: Proper cleanup of loaded configurations

## 📊 API Endpoints Summary

### Core Endpoints
- `GET /health` - Health check with version information
- `POST /query` - Process queries with course support
- `GET /courses` - List available courses
- `GET /courses/{course_id}/config` - Get course configuration

### Request Format
```json
POST /query
{
  "query": "Your question here",
  "course_id": "decision",  // Optional, defaults to "decision"
  "user_id": "optional_user_id"
}
```

### Response Format
```json
{
  "status": "success",
  "data": {
    "answer": "Structured response with tooltips",
    "query": "Original query",
    "course_id": "decision",
    "timestamp": "2024-01-01T12:00:00Z",
    "model": "gpt-3.5-turbo",
    "processing_time": 2.3,
    "conceptsToolsPractice": [
      {
        "term": "Concept Name",
        "definition": "Concept definition"
      }
    ]
  }
}
```
